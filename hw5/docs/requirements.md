# ДЗ № 5. Карта требований на 7 баллов

Пункты 1–4 дают по одному баллу. Пункт 5 оценивается целиком в три балла после выполнения первых четырёх. В таблицах ниже для каждого требования указано, где искать реализацию и по какому признаку её проверить. Команды запускаются из корня проекта.

| Требование | Куда смотреть | Что проверять |

| Описать восемь полей в Protobuf | [MovieEvent](../schemas/movie_event.proto#L20), [Event](../producer/events.py#L17) | `event_id` проверяется как UUID. `user_id`, `movie_id` и `session_id` — непустые строки. Время проверяется на наличие часового пояса и передаётся в UTC с миллисекундами. `progress_seconds` — целое ≥ 0 для событий просмотра. |

Допустимые значения API получены из Protobuf. |
| Зарегистрировать схему с версией | [ensure_schema](../producer/bootstrap.py#L45), [test_topic_and_schema](../tests/test_pipeline.py#L63) | При первом запуске исходный `.proto` отправляется в реестр. При фиксированном числе партиций события одного зрителя попадают в одну партицию, в том числе при смене фильма. Kafka сохраняет порядок записи внутри этой партиции. Аудитория одного популярного фильма распределяется по ключам разных зрителей. |

## 5. Отдельный сервис агрегации

Условие даёт все три балла за сервис, дневные метрики, материализацию и выгрузку в PostgreSQL вместе. Сквозной тест сверяет ожидаемые значения сразу в двух БД. [test_daily_metrics_retention_and_upsert](../tests/test_pipeline.py#L91)

| Требование | Куда смотреть | Что проверять |
|---|---|---|

### Дневные бизнес-метрики

| Требование | Куда смотреть | Что проверять |
|---|---|---|
| DAU | [totals.dau](../aggregation/compute.sql#L21) | `uniqExact(user_id)` считает зрителей с любым событием за UTC-день, включая пользователей, поставивших только лайк. |
| Среднее время просмотра | [totals.avg_watch_seconds](../aggregation/compute.sql#L22) | `avgOrNullIf` усредняет `progress_seconds` только для `VIEW_FINISHED`. При отсутствии завершений сохраняется `NULL`. |
| Топ фильмов | [top_ten](../aggregation/compute.sql#L27), [ranking](../aggregation/compute.sql#L36) | Просмотр считается по `VIEW_STARTED`. Выбираются десять фильмов с наибольшим числом стартов. При равенстве счётчиков порядок определяется по `movie_id`. |
| Конверсия просмотра | [totals.view_conversion](../aggregation/compute.sql#L23) | Число `VIEW_FINISHED` делится на число `VIEW_STARTED` в пределах дня. При нуле стартов результат равен `NULL`. |
| Retention D1 и D7 | [первый просмотр и признаки возврата](../aggregation/compute.sql#L46), [cohort](../aggregation/compute.sql#L54) | Когорта объединяет пользователей по UTC-дате их первого `VIEW_STARTED`. Доля вернувшихся считается отдельно по старту просмотра ровно на 1-й и 7-й день. При пустой когорте или пока целевой день возврата ещё не закончился сохраняется `NULL`. |
| Дневная гранулярность и агрегатные функции ClickHouse | [границы дня](../aggregation/compute.sql#L6), [totals](../aggregation/compute.sql#L18), [группировка истории](../aggregation/compute.sql#L46) | Используются полуоткрытый интервал от начала дня до следующей полуночи UTC и функции `uniqExact`, `avgOrNullIf`, `countIf`, `min`, `max`, `sum`. |
| Материализовать результаты в ClickHouse | [cinema.daily_metrics](../sql/aggregate/clickhouse.sql#L1), [INSERT дневного результата](../aggregation/compute.sql#L2), [чтение с FINAL](../aggregation/storage.py#L81) | Один INSERT сохраняет дневную строку со всеми метриками и топом. В `ReplacingMergeTree(computed_at)` последняя версия определяется по времени вычисления. `FINAL` позволяет сразу прочитать актуальный результат. |
