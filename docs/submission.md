# Сдача работы

1. Изучите `README.md`, C4-диаграмму и `docs/defense.md`. Убедитесь, что можете объяснить границы сервисов и отличие целевой архитектуры от реализованного каркаса.
2. Повторите запуск из README. В ответе `curl` должно быть `200 OK`, у контейнера — `healthy`. Сохранённый протокол находится в `docs/verification.md`.
3. Создайте пустой репозиторий GitHub или GitLab в своём аккаунте. Не добавляйте автоматически README, чтобы не создавать отдельную историю.
4. Из `~/soa/hw1` отправьте подготовленный проект. Если Git ещё не инициализирован, выполните первые две команды; если уже инициализирован, пропустите их.

```bash
git init -b main
git add .
git status
# Выполните, если подготовленные файлы ещё не закоммичены:
git commit -m "Complete marketplace architecture homework"
# Подставьте SSH-адрес своего пустого репозитория:
git remote add origin <SSH_URL_РЕПОЗИТОРИЯ>
git push -u origin main
```

Если `origin` уже настроен, сначала проверьте его `git remote -v`. Не заменяйте адрес чужого репозитория вслепую. Git может попросить настроить имя и email автора — укажите свои данные.

5. На GitHub откройте Actions и дождитесь успешного workflow «Проверка сервиса». При сдаче через GitLab достаточно воспроизводимого Docker-запуска; GitHub workflow там автоматически не работает.
6. Откройте репозиторий в браузере: проверьте README, отображение C4 и доступность преподавателю. Для приватного репозитория потребуется выдать ему доступ.
7. Сдайте ссылку на репозиторий в поле ответа. По присланному условию дедлайн — 2 октября, 23:59.

Адрес удалённого репозитория не задан: автоматически публиковать проект в произвольный аккаунт нельзя. Папка и архив содержат все материалы для загрузки. Отчёт не заменяет ссылку на репозиторий, которую требует задание.
